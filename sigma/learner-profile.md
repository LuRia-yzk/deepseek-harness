# Learner Profile

Updated: 2026-10-28

## Learning Style

- Preferred explanation mode: **具体例子 + 从自己的使用者经验倒推**。最有效的一次是「`pnpm dsh web` 里的 `web` 就是 profile 名」——用他已经做过的事当锚点，远好于讲定义。
- Pace: **慢**。单轮认知负荷低，一次只问一个问题时表现最好；同时问两题时第二题经常空着不答。
- Responds best to: **讲回（teach-back）**、**反例预测**、**去仓库自己找证据**、**跨语言类比**。他熟悉 C，「字典 ≈ 下标可以是字符串的数组」「交出 5 时 5 不会运行」这类对照一次就通。
- 最有效的锚点类型：**语义锚 + 代码落地 + 最小独立例子**。纯语义锚会翻；指到具体文件行号就稳；但**语言级概念必须用"离开 dsh 的最小例子"**，套在 dsh 代码里讲会卡住。
- 语言基础是长期短板（已撞到：`import type`、`abstract`、`super`、`new`、`implements`、箭头函数、`() => {}` 不执行、类型标注、分号、**嵌套调用 `f(g({...}))` 的括号归属**）。**已交付 `dsh-plugins/visuals/js-ts-minimum.html` 作为常备字典**（约定：不通读，撞到再查）。
  - **10-19 发现：语言层地基会跟复习间隔一起衰减。** 「造函数 ≠ 调用函数」在 10-12 已焊死，7 天后预测 `const 清理 = 挂监听()` 的输出又答错（以为会打印两行）。给一个 `return 5` 级对照 + 一行字级别复原，**一轮收回**。→ **每轮复习开场先用 10 秒的最小例子验它**，别等它把概念 5 整条链带塌。
    - **10-20 复验：同样的小例子隔夜仍答对**（「挂上了 / --- / 撤掉了」），说明 10-19 的补课有效。
  - **C 骨架是万能翻译层（10-20 确认）。** 讲不通"运行时到底发生什么"时，直接写成 C：事件分发写成「函数指针数组 + for + strcmp」，他立刻推出"没人匹配 → 循环跑完 → 当场返回"，并推翻自己「后台等待」的说法。**规则：任何"程序跑起来会怎样"讲不通，先落地成 C 骨架，再回到 TS。**
  - **执行缺口（10-20）**：手写代码时漏函数参数（`apply()` 忘写 `ctx`）、事件名不加引号、把"一个字符串名字"用逗号拆成两个变量。**概念没错，是笔头没跟上**——练习时要单独留出书写时间，别用口头答案替代。
- Struggles with: **抽象名词实体化**；**术语未落地时的标签翻转**（第一号模式，已缓解）；**把"写法"当成"执行"**（见第 04 号）。

## Misconception Patterns

- **【第一号】术语没落地 ⇒ 标签翻转**（截至 2026-10-11 共 5 次，**10-11 之后未再翻转**）：能复述定义，配对时却把两者对调。
  - **根因在术语层，不在核对习惯。** 反制：把每个术语指到具体文件与行号。
  - **10-12 验证继续有效**：他自主用"有没有 `super`"推断出 `remotes` 是函数形态——这是第一次**主动迁移**该判据。
  - **10-18 复发（不翻转，但变空词）**：问「fs 是代表什么吗」——六天不做，`fs` 又变成无内容的词，导致整条推理推不动。**空词复发不等于翻转复发**：他不再把两个标签对调，而是根本没东西可对调。反制同上（指到文件行号），且**每次复习第一题就该先验术语是否还实心**。
  - 测量含义：**不能用二选一配对题测他**；要用"无标签复述"或新场景应用。
- **【第二号】"看着像就当成是"**：`printf` 当成 JS 打印、`applyLiteralEdit` 当成插件 `apply`、样本包名当成自己的、`new` 后面的类名当成"对象的名字"、npm 的"消费方"当成 Cordis 的"消费方"、`ctx.typertGateway` 当成函数（实为对象）。**共性是"看到相似形状就下判断，不核对"**——遇到新东西提醒他先确认"这是什么"。
  - **10-20 实测：换变体就套旧答案。** 复习时把 `const 清理 = 挂监听()` 改成调两次、只执行 `b()`，他直接复述上次的三行答案。三问即收回。→ **复习题必须变体，不能重复原例；并且当面点破"这次真的完全一样吗"。**
- **【第三号】定义函数 ≠ 调用函数**（10-12 攻克，是最顽固的一个）：把 `return () => {...}` 理解成"要执行大括号里的代码"，因而推出"刚登记就被卸下"。
  - **唯一奏效的讲法**：用 `return 5` 对照——"交出 5 的时候 5 不会运行"；再加"末尾多一对括号"的正反对照。
  - 教训：**讲"造函数/调用函数"不够，要讲"返回值是值，值不会自己运行"。**
- **把"能力"实体化为"东西"**：fs → 文件夹；内核 → 某个具体部件；ctx → 文件。
- **把"必需"等同于"不可动"**：已用"发动机≠车架"纠正并成功迁移。
- **机制推理与结论脱钩**：能推出正确机制却保留旧结论。反例必须**由他自己给出的两句话拼成**才有效。

## Metacognition

- Self-assessment accuracy: **整体偏保守（五次自评略低于实际，从无高估），但不等于可以忽略。**
  - **10-22 反例：他自评"发虚"，我判 4/4；复查后确认他五处都要提示，改判 3/4。这一次自评比评分准。**
  - 结论：**自评必须恢复为例行环节，且要当作证据使用**，不能因为"他总是偏保守"就跳过。他还会主动发现流程被省掉（10-22：「为什么没先询问我自己的评价了」）——这种对学习过程本身的敏感度要保护。
  - **10-23 再次命中：第 10 站自评「发虚」，复查后确认只有一问一次答对，从 4/4 下调为 3/4。两次「发虚」两次都准。** → 定级前必问自评；自评「发虚」时默认先按 75% 处理，除非复查证据明显更强。
- **最强项：能主动声明"我这个理由是二手推出来的"。** 这一句把教学方向从"补标签"改到"补地基"，是全程最大转折。**遇到他答对但理由含糊时，主动追问"这是你自己推的，还是从我的话里提取的"。**
- 第二强项：**卡住时会主动说"我不理解 X"并精确指出是哪一个语法**（10-12 直接说"我不太理解 `const 清理 = 登记()`"）——**这种精确报点让排障极快，要鼓励。**
- Fluency illusion frequency: **低**。反而会把"卡了很多次"误读成"我没学会"。
- 疲劳特征：长会话后段会把已掌握的概念选错。**他会在累的时候主动说"需要休息"或"先到这里"，且常在休息前要求"先把这一块搞清楚"——这个习惯要保护。**
- 其他强项：**能主动提出"为什么要有这个东西"级别的设计问题**（"为什么还要子类"直接命中能力 seam 核心）。
- **新增强项（2026-10-18）：会审题。** 复习时他主动质疑我给的论证本身（"两个文件可以互不相干"），且质疑正确——我从"学习者"往"审稿人"挪了一步的信号。**今后可以开始给他略带缺陷的材料让他挑错。**
- **复习节奏的经验值**：间隔 6 天后，已掌握概念的机制仍在，但**术语变空词 + 无法自主检索**，必须靠脚手架才可达。建议复习间隔控制在 **2–4 天**，不要按翻倍机制推到 8 天以上。
- **新增强项（2026-10-28）：会提架构改进。** 学完 loader / bundle / patch 之后，他主动提出"写个插件在运行时覆盖，而不是抄一份快照，这样 DSH 升级不受影响"——**这个方向正确，且官方 API（`readDocument` + `register`）恰好支持**。这是从"理解机制"到"用机制设计解法"的第一次跨越。
  - 教学含义：**他开始能评价方案的好坏（可维护性、抗变更），而不只是对错。** 今后讲完一个机制，可以加一问"如果上游改了你怎么办"。
- **对材料的要求升级（2026-10-28）**：连续两次被我给错事实后，他开始要求"先去查查有没有人分享过"「官方是怎么写的」——会把我的断言当**待验证**而非结论。这是好事，**但要付代价：每次给事实前必须自己先查证**，否则消耗信任。
- **能做风险取舍（2026-10-28）**：面对 danger-full-access 的取舍，他用自己的使用经验判断（「Claude Code 用了很久没出问题」）并承担结果，而不是要求"绝对安全"。**这类决策交给他是对的。**
- **长会话耐受比预期好**：2026-10-27 15:56 → 10-28 00:20（含多次休息）仍在提架构级问题；但**书写类错误在连续 8 小时后明显上升**，笔头训练应安排在会话前段。
