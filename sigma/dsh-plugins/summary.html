第 09 站：树是怎么拼出来的

[]                          # cordis.yml —— 空，故意的
  ↓ dsh-base 自带的 patch
  ↓ dsh-web-app 自带的 5 份 patch
  ↓ voice-input 自带的 patch
  ↓ 你自己的 cordis.patch.yml ← 最后贴，所以它说了算
  = 一棵几百个插件的树
  • 从空开始不是省略，是承诺。你自己的话：「要保证 dsh 一切皆插件，所以该文件是空的」——第 01 站和第 09 站在这里接上了。
  • 特权的定义：不是"改不改得动"，是"不点名时在不在"。空清单让所有插件都必须被点名。
  • 后贴的覆盖先贴的（跟 C 的 x = 1; x = 2; 同性质）。所以别改安装目录里那份——升级就没了。

08 和 09 在这里合上了

  • cordis.patch.yml 是 YAML，TS 的类型检查看不见它。
  • 那里面每个 config: 块的唯一关口，是那个插件导出的 Config schema。
  • schema 不是表，是校验器：能被调用，干三件事——查类型范围、补默认值、产出干净配置。apply 拿到的是成品。
  • 没有 Config = 没有校验器 = 静默（跟"没人监听就不报错"同一个形状）。
一句话：类型管代码，schema 管配置，谁都不管的东西就静默通过。
