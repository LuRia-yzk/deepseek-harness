目录是怎么确定的？

你问的这个问题是真的挡路了。补上它，前面所有推理才走得通。

// 聊天代码里唯一出现的"位置信息"
const text = await fs.readText('notes.txt')
注意：聊天给的是一个相对路径 'notes.txt'——没有盘符，没有 C:\，没有 /home/。
相对是相对于谁？这就是全部的关键。

01三步走完

1
聊天只说"读 notes.txt"。它不说是哪台机器上的。
2
fs 这个零件自己带着一个"根目录"。这是它的配置，不是聊天代码给的。
3
实际去读的位置 = 根目录 ＋ 聊天给的那个相对路径。

02同一行代码，两种环境

笔记本上的那次装配

聊天说'notes.txt'
这份 fs 的根目录C:\Users\你\my-project
实际读到C:\Users\你\my-project\notes.txt

服务器上的那次装配

聊天说'notes.txt'
这份 fs 的根目录/workspace（沙箱里）
实际读到/workspace/notes.txt
聊天代码一个字都没改，但它读到了两台不同机器上的文件。
因为"根目录"这件事是那份 fs 实现自己带着的，跟聊天没关系。
所以要记住的三件事：
① 目录 不是 fs 决定的，也 不是 聊天决定的——是 fs 那份实现的配置 决定的。
② 目录是"被操作的对象"，fs 是"操作者"。两者是分开的两件事。
③ 因此换掉 fs 的实现，也就换掉了"哪台机器上的文件"——但聊天代码不需要知道这件事。
