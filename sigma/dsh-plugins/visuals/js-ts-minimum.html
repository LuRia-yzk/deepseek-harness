01模块：import / export

具名导出：名字由「导出方」定死

// a.ts
export const name = 'sigema'
export function apply() {}

// b.ts —— 必须用同一个名字
import { name, apply } from './a.ts'

默认导出：名字由「导入方」随便起

// a.ts
export default class Foo {}

// b.ts —— 叫什么都行
import 爱叫啥叫啥 from './a.ts'

import type：只借"类型说明书"，运行时不存在

import type { Context } from '@deepseek-ai/cordis'
// 编译后被整个删掉，不能拿来调用任何东西
看到 type 这个词 = 运行时不存在。
import type {} from '...'（空的大括号 + type）是 DSH 常用的技巧：只为了触发声明合并，一行东西都不引入。
在 dsh 里 → edit.ts 只 import type 了 fs，实现是用 ctx.fs 取的。

02函数的三种写法

// ① 声明式
function 打招呼(名字) { return '你好，' + 名字 }

// ② 箭头函数（更短，最常见）
const 打招呼 = (名字) => { return '你好，' + 名字 }

// ②b 只有一句 return 时还能再省
const 打招呼 = (名字) => '你好，' + 名字

// ③ 对象/类上的方法
class 问候器 {
  打招呼(名字) { return '你好，' + 名字 }
}
() => { ... } 里那个空括号 = 不收参数。整体意思是"一个被调用时才会执行的函数"。
参数标注类型的写法是 名字: 类型，例如 (ctx: Context)。
在 dsh 里 → apply.ts 有 () => ctx.typertGateway.registerRemoteEvents(...)：一个不收参数、调用时才执行的函数。

03造函数 ≠ 调用函数你踩过

function 登记() {
  console.log('我登记了！')
  return () => { console.log('我取消了！') }   // 只是"造"一个函数
}

const 清理 = 登记()    // 打印：我登记了！   （清理 = 那个函数）
console.log('---')        // 打印：---
清理()                   // 打印：我取消了！   ← 加了括号才执行
看到 () => { ... } 或 function () { ... }，那是"造了一个函数"，不是"跑了一段代码"。
它静静躺着，等着有人给它加一对括号 ()。

const x = f()：右边先跑——先调用 f()，再把返回值装进 x。
在 dsh 里 → provide() 里 store[key] = impl 是真的执行；紧跟的 return () => { delete ... } 只是把清理办法交出去，此刻一行都没跑。

04类：class / extends / super / new

class 动物 {
  constructor(名字) {        // 构造函数：new 的时候自动跑
    this.名字 = 名字          // this = 正在被造出来的那个对象
  }
}

class 猫 extends 动物 {       // 继承：猫 = 动物 + 补充
  constructor() {
    super('猫')               // 调用父类的构造函数，把 '猫' 传上去
  }
}

const a = new 猫()            // new = 用模具造一个对象
词意思
class定义一个类（模具）
extends继承——只发生在类与类之间，没有"继承一个对象"
super(...)语言关键字（不定义在任何文件里）：调用父类的构造函数
new X(...)用 X 这个模具造一个对象。new 后面跟的是类，不是"对象的名字"
this正在被造出来的那个对象自己
在 dsh 里 → class FileSystem extends Service + super(ctx, 'fs')：Service 的构造函数里写着登记代码，所以只有它的子类登记得了。

05abstract 与 implements

interface 可打招呼 {                      // 接口：一份"要求清单"（纯类型）
  打招呼(名字: string): string
}

abstract class 文件系统 {              // 抽象类：只有说明书，不能 new
  abstract 读文件(路径: string): string  // 只写"必须有什么"，不写"怎么做"
}

class 本地文件系统 extends 文件系统 implements 可打招呼 {
  读文件(路径) { return '真的去读' }
  打招呼(名字) { return '你好' }
}
abstract = "半成品模具，不许直接 new"。
implements X = "我承诺满足接口 X 的所有要求"——纯给编译器检查用，编译后消失。

06类 vs 对象

类对象
是什么模具、图纸模具压出来的产品
住在哪源码里（.ts 文件）内存里（跑起来才有）
有几个写一次就一个想要几个造几个
怎么来class X { }new X()
有名字吗有（类名，给人看）默认没有，得被变量或容器接住
对象 = 一堆数据 + 一堆方法，打包在一起。
对象身上的数据叫属性（obj.name），身上的函数叫方法（obj.editText()）。

07类型标注、interface、泛型

// 名字: 类型      —— 冒号后面永远是"类型"，不是变量名
function apply(ctx: Context, config: Config): void {}

interface Config {          // 定义一份"对象的形状"
  cwd?: string              // ? = 可选
}

type Name = string          // 给类型起个别名

// 泛型：类型也是参数
class Store<T> { get(): T }
const s = new Store<string>()
全部 只在编译期存在。运行时这些标注一个都不剩——所以类型写错只会在编辑器/编译时报错，不会让程序运行时崩。
在 dsh 里 → Service<out T = never>、Dict<Impl, symbol>、Config?: string 里的 ?（可选）。

08async / await / Promise

async function 读文件() {          // async = 这个函数"要等"
  const 内容 = await 异步操作()   // await = 在这儿等结果，等到了再往下走
  return 内容
}

// 调用 async 函数，拿到的是一个 Promise（"将来会有结果"的凭据）
const p = 读文件()
Promise = "现在还没有，将来会有的东西"。
await = 在那儿等它兑现。async = 声明"我里面会 await"。
() => Promise<void> 读作"一个返回 Promise 的函数"——DSH 里的 disposer 常常长这样。
在 dsh 里 → registerRemoteEvents(...): () => Promise<void>：它返回的清理函数是异步的（清理要等后台任务真的停）。

09对象、点、解构

const 人 = { 名字: '小明', 年龄: 18 }   // {} = 造一个对象（也是字典）

人.名字                // 点：按名字取属性
人['名字']            // 方括号：按"字符串键"取 —— 和点是一个意思

const { 名字, 年龄 } = 人      // 解构：把属性拆进变量
const [第一, 第二] = 数组      // 数组按位置拆

const { a = 1 } = obj          // 默认值：没有就用 1
JS 的对象就是一本字典（键是字符串，值是任何东西）。
所以 ctx.fs 和 ctx['fs'] 完全等价——一个是语法糖，一个是原形。
在 dsh 里 → ctx.fs.editText(...) 读作：从 ctx 取属性 fs（拿到一个对象）→ 从那个对象取属性 editText（拿到一个函数）→ 调用它。两个点 = 两次取属性。

10几个高频小符号

符号名字意思
?.可选链a?.b —— a 是空的就返回空，不报错
??空值合并a ?? b —— a 是空的就用 b
??=空值赋值a ??= b —— a 是空的就赋成 b
...展开 / 收集{ ...a, b: 1 } 复制 a 再加一项
=>箭头定义函数
;分号可以省略，JS 会自动补。dsh 仓库的风格是一律不写
// /* */注释和 C 一样
/** */JSDoc写在声明上方的说明块，dsh 每个模块和导出都有
在 dsh 里 → name ??= this.constructor['provide'] 读作："如果 name 是空的，就用类上那个 provide 字段"。
