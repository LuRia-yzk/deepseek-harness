super 是什么，以及为什么子类「少一个参数」

你在 service.ts 里找不到 super —— 那是找对了地方，找错了对象。

01结论：super 不是「东西」，是「关键字」

你去 vendor/cordis/src/service.ts 里找 super 的定义，找不到。

那里面本来就没有。

super 是 JavaScript 语言本身的关键字，和 if、return、class 是同一类东西。
你不会去找 if 的定义，同理也不用找 super 的——它不是谁写的函数，是语言规定好的语法。

它的含义固定不变：
在子类的构造函数里，super(...) = 调用父类的构造函数。

02一个最小例子（先离开 dsh）

class 动物 {
  constructor(名字) {
    this.名字 = 名字
  }
}

class 猫 extends 动物 {
  constructor() {
    super('猫')          // ← 调用父类构造函数，把 '猫' 传上去
  }
}

new 猫().名字            // → "猫"
注意三件事：
① 猫 的构造函数不收参数——因为它自己知道该叫什么
② super('猫') 把"名字"转交给父类去处理
③ 父类的 constructor(名字) 收到 '猫'，执行 this.名字 = '猫'

03映射回 dsh：一模一样的结构

你的最小例子dsh 里
class 动物class Service（vendor/cordis/src/service.ts）
constructor(名字) { this.名字 = 名字 }constructor(ctx, name) { ... provide(name, self) }
class 猫 extends 动物class FileSystem extends Service
constructor() { super('猫') }constructor(ctx) { super(ctx, 'fs') }
结构完全一样。你发现的那个"少一个参数"，就是这么来的。

04参数是怎么流的

packages/fs/fs/src/index.ts
  constructor(ctx)  ← 子类只收 1 个参数
    └─ super(ctx, 'fs')  ← 自己补上第 2 个（写死的名字）
                 ↓
vendor/cordis/src/service.ts
  constructor(ctx, name)  ← 父类收 2 个
    └─ ctx.reflect.provide(name, self, ...)  ★ 登记发生在这里
FileSystem 不需要问别人"我叫什么"——它自己知道它叫 fs。
所以它只要求外面给它一个 ctx，名字那一格它自己填。
于是那句话终于落地了：「只有 Service 的子类能登记」

这不是一条规矩，是一条路径：

你想登记
  ↓
必须执行 ctx.reflect.provide(...)
  ↓
这行只写在 Service 的构造函数里
  ↓
想跑到它，只能 extends Service 然后 super(...)
  ↓
所以函数做不到——函数没有父类，也就没有 super
